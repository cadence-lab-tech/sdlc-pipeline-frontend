# Cadence Lab — Frontend

Интерфейс системы, ведущей задачи по настраиваемому циклу разработки: доска
задач, карточка задачи с таймлайном и артефактами по этапам, редактор ролей и
редактор цикла с гейтами.

Бэкенд: [sdlc-pipeline-backend](https://github.com/cadence-lab-tech/sdlc-pipeline-backend) ·
Установка у себя: [cadence-lab-tech/self-hosted](https://github.com/cadence-lab-tech/self-hosted) ·
Лицензия: FSL-1.1-ALv2 (раздел [«Лицензия»](#лицензия))

## Стек

Vite, React 19, TypeScript, Tailwind CSS 4 и
[shadcn/ui](https://ui.shadcn.com) на примитивах Radix.

Компоненты shadcn лежат в `src/components/ui/` исходниками, а не приезжают
зависимостью: их правят под себя, а новые добавляют командой
`npx shadcn@latest add <имя>`. Тема светлая и тёмная, переключатель — в шапке.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173, /v1 проксируется на бэкенд
```

Бэкенд поднимается отдельно (`cd ../backend && make up`) на `localhost:8088`;
адрес переопределяется переменной `SDLC_API_URL`, порт dev-сервера —
`SDLC_UI_PORT`.

Когда параллельно идут несколько задач, у каждой свой стек бэкенда и свой порт
интерфейса — иначе агенты мешают друг другу тестовыми данными:

```bash
cd ../backend && dev/stack.sh up CLAB-39      # поднимет api и напечатает порты
cd ../frontend
SDLC_API_URL=http://localhost:18080 SDLC_UI_PORT=5180 npm run dev
```

Подробности — `backend/dev/README.md`, раздел «Стек на задачу».

Вход зависит от режима бэкенда. При `SDLC_AUTH_MODE=header` действующее лицо
уезжает в заголовке `X-SDLC-Actor` (по умолчанию `web`, хранится в
`localStorage`) и права не проверяются — это режим отладки цикла. При
`SDLC_AUTH_MODE=token` нужен токен: его вводят на странице входа или получают
входом через корпоративного провайдера, если тот настроен
(`SDLC_OIDC_ISSUER`). Вход через провайдера идёт кодом авторизации с PKCE, а
ID-токен меняется на обычную сессию бэкенда — второго транспорта у системы
нет.

```bash
npm run typecheck
npm run lint
npm run build
npm run e2e      # сквозные проверки в headless-Chrome поверх живого бэкенда
```

Продовый образ — `Dockerfile`: сборка Vite, статика в Caddy с откатом на
`index.html` для маршрутов React Router. Caddy образа собирается из
исходников (`caddy/`: версия Caddy и модулей в `go.mod`/`go.sum`, текущий
Go 1.26), а не берётся из `caddy:2-alpine` как есть: upstream на новом Go
его не пересобирает. Образ работает от uid 65532 и слушает `:80` и `:8080`;
`CADENCE_UI_ADDRESS` сужает адрес (чарт пакета ставит `:8080`). Тот же образ
в пакете self-hosted работает и точкой входа стека — там от root
(`user: "0:0"` в compose). Адрес API в бандл не вморожен:
клиент ходит в `/v1` того же origin, к сервису его ведёт внешний Caddy из
`backend/deploy`. Пуш в `main` собирает образ в GHCR и выкладывает его
(`.github/workflows/deploy.yml`); как устроен стек —
[deploy/README.md](https://github.com/cadence-lab-tech/sdlc-pipeline-backend/blob/main/deploy/README.md)
в репозитории бэкенда.

Выпуск версии — тег `vX.Y.Z` на `main` здесь и тот же тег в
[backend](https://github.com/cadence-lab-tech/sdlc-pipeline-backend). Тег
здесь запускает `.github/workflows/release.yml`: образ
`ghcr.io/cadence-lab-tech/sdlc-pipeline-frontend:vX.Y.Z` с файлом `LICENSE`
из корня репозитория по пути `/LICENSE`; без `LICENSE` выпуск падает до
сборки, а `deploy.yml` тег не запускает. С v0.9.0 у образа в индексе SBOM
(SPDX, вместе с npm-пакетами этапа сборки — `BUILDKIT_SBOM_SCAN_STAGE` в
`Dockerfile`) и provenance (SLSA v1), а digest индекса подписан cosign без
ключей — identity `release.yml` этого репозитория на теге ([решение
0046](https://github.com/cadence-lab-tech/sdlc-pipeline-docs/blob/main/decisions/0046-supply-chain-signatures-pins.md)).
После v0.12.0 к digest приложен и OpenVEX из `.github/release/openvex.json`:
известные ложные находки сканеров с обоснованием.
Тот выпуск, что опубликовал и подписал образ вторым, шлёт событие
`cadence-release` с digest обоих образов в
[`cadence-lab-tech/self-hosted`](https://github.com/cadence-lab-tech/self-hosted)
(`.github/release/notify-self-hosted.sh`, такой же в backend; проверка —
`bash .github/release/notify-self-hosted.test.sh`). Нужны секрет
`SELF_HOSTED_DISPATCH_TOKEN` (fine-grained PAT с Contents: Read and write
только на `self-hosted`); пакеты GHCR публичные, и образ соседа прогон
читает своим `GITHUB_TOKEN`. Пришла только половина выпуска — в логе шага
«оповестить self-hosted» написано, какого образа нет: поставить тег во
втором репозитории или перезапустить упавший прогон. Отказ реестра
(401/403) и молчание сети шаг за отсутствие образа не выдаёт — такой
прогон красный, с командой для отправки руками (CLAB-99). Подробно —
раздел «Выпуск версии» в
[README бэкенда](https://github.com/cadence-lab-tech/sdlc-pipeline-backend#выпуск-версии).

## Страницы

| Страница | Назначение |
|---|---|
| Projects | Список проектов, репозитории в области проекта |
| Teams | Команды: состав, доступ в проекты, группы провайдера, бюджет |
| Principals | Кто заведён в системе; видна администратору системы |
| Audit | `/audit`: журнал действий уровня инстанса — команды, принципалы, токены без проекта; видна администратору системы |
| Board | Доска задач по статусам действующего цикла, создание задачи |
| TaskDetail | Этапы с артефактами, вердикт гейтов, переходы, область и свойства, лента с подробностями событий, журнал действий |
| Roles | Роли и их версии: инструкция, вход, контракт вывода, где роль стоит |
| WorkflowEditor | Версии цикла: черновик, статусы, переходы, гейты, проверка, активация |
| Metrics | Длительность статусов, вердикты гейтов, дрейф, стоимость, пропускная способность |
| Settings | Участники с ролями специалистов, команды проекта, доступ к GitHub, токены, перенос связки, журнал действий проекта |
| Login | Вход токеном, через GitHub или через корпоративного провайдера |

## Что интерфейс не делает

- **Не считает, можно ли перейти.** Вердикт по каждому гейту приходит из API;
  экран его показывает и даёт закрыть то, что закрывает человек.
- **Не двигает задачу перетаскиванием карточек.** Между статусами задачу
  переводит именованный переход со своими гейтами, и в одну колонку могут
  вести разные переходы — «сдать» и «вернуть».
- **Не решает, кому что можно.** Права проверяет бэкенд: 403 показывается как
  обычная ошибка, а кнопки по уровню участника не прячутся. Исключение одно —
  список принципалов: он общесистемный и лиду команды не отдаётся вовсе.
- **Не проверяет ID-токен провайдера.** Браузер получает его кодом
  авторизации и отдаёт бэкенду; подпись, издателя и аудиторию проверяет тот.
  Код от GitHub браузер тоже только передаёт: секрет клиента живёт на бэкенде.
- **Не правит активный цикл.** Правка — черновик, который активируется
  целиком.

## Статус

Закрыты фазы 1, 4, 5 и 6: доска с переключением типа задач, карточка задачи с
нарезкой эпика, стоимостью и назначением, редакторы ролей и цикла, метрики,
вход и права, перенос связки, команды с бюджетами, вход через корпоративного
провайдера и настройка доступа к GitHub у проекта. Сквозные проверки проходят.

Выход к коллегам:
вход через GitHub, роли специалистов у участников и команд проекта, создание
проекта со страницы проектов.

Не сделано: аренды и живой прогресс агента, вложенные прогоны перепроверки
(фаза 2), сигналы дрейфа, состояние индекса и поиск (фаза 3) — REST всё это
уже отдаёт.
